# HLS 直播连续录音采集

电台语料采集工具：把直播 HLS 流录成连续录音包，交给离线转写。
FastAPI + SQLite 采集网页，输入媒体清单地址即开始追随录制；停止后把应收片段
全部落盘，产出可离线播放的 ZIP（本地 M3U8 + 原始 TS 片段，不引用远端）。

内置**录音对照**：电台编辑比较同一节目的两次录音，定位起录时间不同或换播
造成的原始片段差异。网页上选择两份已完成录音的 ZIP，按包内 M3U8 顺序读取
TS 片段并比对字节指纹（SHA-256），给出保序的共同片段对照与确定独有清单。

## 运行

```bash
docker compose up --build
# 网页:  http://localhost:8000
# 直播源: http://localhost:8080
```

网页中可开始录制、停止、查看进度、下载 ZIP、对照两份已完成录音。直播源地址
示例（网页内也有提示）：

| 用途 | 地址 |
|---|---|
| 普通滑窗直播 | `http://livesource:8080/live.m3u8` |
| 慢下载（每段延迟 1.5s） | `http://livesource:8080/live.m3u8?delay_ms=1500` |
| 缺段（指定序号返回 404） | `http://livesource:8080/live.m3u8?missing=12,13` |
| 窗口跳号（越过未发现序号） | `http://livesource:8080/live.m3u8?jump_at=10&jump_by=8` |
| 每段内容唯一（可逐段对照） | `http://livesource:8080/live.m3u8?uniq=1` |
| 换播（指定序号内容不同） | `http://livesource:8080/live.m3u8?uniq=1&alt=20,21` |
| 有限节目（部分重叠对照样例） | `http://livesource:8080/prog.m3u8?first=1&count=8&uniq=1` |
| VOD（带 ENDLIST） | `http://livesource:8080/vod.m3u8` |
| 非法样例（master/加密/不连续） | `/master.m3u8` `/enc.m3u8` `/disc.m3u8` |

对照样例：分别录制 `prog.m3u8?first=1&count=8&uniq=1` 与
`prog.m3u8?first=3&count=8&uniq=1&alt=6`，两期节目部分重叠且第 6 段内容
不同，对照可确定定位重叠区与各自独有段。

## 行为规则（与需求对应）

- **接受的清单**：仅单层媒体清单（拒绝 master）、未加密（拒绝非 NONE 的
  `EXT-X-KEY`）、无不连续标记、MPEG-TS（片段须为 `.ts`，拒绝 `EXT-X-MAP`），
  片段地址在清单内与整个录制任务内均不得复用。
- **追随滑窗**：从首份清单首段（其 `EXT-X-MEDIA-SEQUENCE`）开始，按媒体序号
  判定连续性；新清单起点越过 `last_seq+1` 即判失败并列出缺段序号。
- **停止**：受理时把边界固定为最后已接收清单的尾段并立即持久化，此后不再
  延长范围（拉取途中的清单若晚于停止到达会被丢弃）；重启后边界不变。
- **完成**：边界内全部片段保存后才生成并开放 ZIP；ZIP 内含本地
  `playlist.m3u8`（`EXT-X-ENDLIST`，仅引用包内文件）与原始片段。
- **失败**：应收片段 404、窗口跳号、源违反约束、持续拉取/下载失败均判失败，
  失败任务列出缺段且不提供下载，不会跳过后报成功。
- **持久化**：片段与 ZIP 存持久卷（`/data`，compose 命名卷），SQLite 只存
  进度（任务状态、边界、每段状态）。落盘用临时文件 + 原子 rename；
  重启时对账磁盘与 DB——已落盘未登记的片段收养为完成，登记完成但文件丢失
  的重新下载；已保存片段即使滑出清单也保留并入包。
- **并发**：每路录制为独立的异步轮询 + 下载任务（asyncio/httpx），支持两路
  （及以上）同时录制；慢下载不阻塞另一路、停止受理与查询。

## 对照行为规则

- **输入**：两份已完成（`done`）录音的 ZIP。按各自包内 M3U8 的顺序读取 TS
  片段，以字节内容的 SHA-256 作为指纹。
- **保序匹配**：共同内容按最长公共子序列（LCS）刻画，匹配保留播放顺序，
  不做集合式乱序配对。
- **确定与待定**：出现在**所有**最优对齐中的配对才列为"确定共同"；不出现在
  **任何**最优对齐中的序号才列为"确定独有"（给出两侧序号与包内文件名）。
  相同内容反复出现、缺失位置无法唯一确定时，最优对齐不唯一——此时只列出
  两侧可能范围（待人工核对区域），不任选一处当作确定结论。
- **无法定位**：两包没有共同片段时明确说明无法定位差异位置。
- **不发布结果**：清单引用的片段在包内缺失、包文件损坏/缺失、对照期间包被
  改写（读取前后文件签名不一致）、包超出对照规模上限时，对照失败且不发布
  结果（仅记录原因）；原录音 ZIP 的下载不受任何影响。
- **结果留存**：对照报告持久化（SQLite），含两包内容签名，供事后核对当时
  对照的是哪一份内容；报告是发起时的历史快照，包事后被外部改动不会使已
  发布的报告失效，需重新发起对照。
- **规模上限**：单包 ≤ 20000 段，且两包段数乘积 ≤ 2500 万（约 5000×5000，
  最坏情况对照约需数十秒）；超出拒绝对照并说明。

## API

- `POST /api/jobs` `{url}` 开始录制
- `POST /api/jobs/{id}/stop` 停止（固定边界）
- `GET /api/jobs` / `GET /api/jobs/{id}` 进度（状态、窗口、缺段、错误）
- `GET /api/jobs/{id}/download` 下载 ZIP（未完成返回 409）
- `POST /api/comparisons` `{job_a, job_b}` 发起对照（异步执行）
- `GET /api/comparisons` / `GET /api/comparisons/{id}` 对照状态与报告

任务状态：`recording` →（停止）→ `finalizing` → `done` / `failed`。
对照状态：`running` → `done`（含报告）/ `failed`（只有原因，不发布结果）。

报告要点：`common_blocks`（确定共同的两侧序号区间）、`unique_a`/`unique_b`
（确定独有的序号与包内文件名）、`ambiguous_regions`（无法唯一确定的两侧
可能范围，供人工核对）、`status=no_common` 表示两包没有共同片段。

## 目录

```
app/          采集网页与录制引擎（FastAPI）
  src/playlist.py   严格清单解析与校验
  src/recorder.py   轮询、下载、定界、打包、重启恢复
  src/compare.py    录音对照（读包校验、保序对齐、确定/待定判定）
  src/db.py         SQLite 进度存储（录制任务 + 对照结果）
livesource/   本地伪直播源（滑窗/延迟/缺段/跳号/唯一内容/换播/有限节目/非法清单样例）
docker-compose.yml
```

## 测试

本仓库代码已在本地以与容器相同的命令（`uvicorn src.main:app`）完成端到端
自测：基本录制-停止-打包、ZIP 内容校验（本地清单/连续序号/无远端引用/
片段字节一致/ffmpeg 可解码）、两路并发与慢源不阻塞、缺段 404 失败、窗口
跳号失败、非法清单拒绝、ENDLIST 自动定界、崩溃（`os._exit`）后重启续录、
停止边界重启不变、落盘与登记之间崩溃的收养恢复；对照的起录不同/换播确定
定位、重复内容只给可能范围、无共同片段说明、清单缺段与对照期间改写不发布
结果且原下载可用，共 76 项全部通过。

- `tests/test_e2e.py` 录制主流程（26 项）
- `tests/test_extra.py` 地址复用拒绝 + ffmpeg 解码（3 项）
- `tests/test_align.py` 对照算法单元测试（26 项，直接 `python3` 运行）
- `tests/test_compare.py` 对照端到端（21 项，自带源与应用进程）

测试钩子（仅 `RECORDER_TEST_HOOKS=1` 时挂载，compose 不启用）：

在指定片段落盘后、登记前崩溃；`POST /api/_test/arm_zip_rewrite/{job}` 使下一次

`POST /api/_test/exit`（测试进程自我退出）。

## 已知限制

- 单进程部署（任务状态在内存中，重启时从 SQLite + 磁盘恢复）；不支持多
  worker 水平扩展。
- 片段按字节原样保存，不做码流级完整性校验。
- 非 404 的持续性下载错误重试 5 次后判失败；清单持续拉取失败 15 次后判失败。
- 本地直播源默认各片段内容相同（种子片段循环），`uniq=1` 时每段为种子字节
  + 确定性后缀（仍为可解码 TS）；时间戳每段重置，ffmpeg 解码校验通过，
  拼接播放时个别播放器可能提示时间戳不连续。
- 对照只接受本服务已完成录音的 ZIP（网页中选择任务），不支持上传外部 ZIP。
- 对照的"包被改写"检测基于读取前后的文件签名（dev/inode/大小/mtime），
  与读取过程中的 ZIP/CRC 校验；无法防御读取间隙内同签名替换的理论窗口。
- 对照规模上限见"对照行为规则"；超过上限的录音暂不支持对照。
